# 會議助手

本機執行的會議紀錄工具：**一邊開會一邊錄音轉逐字稿、一邊打字做筆記，會後用 LLM 產出 markdown 會議紀錄。**

- 轉錄可選 **Gemini（有免費額度）** 或 **Typeless（付費、中文品質好）**
- 錄音檔、逐字稿、筆記、會議紀錄都存在自己的硬碟；音訊會送到你選的轉錄服務（Google 或 Typeless）
- API key 只存在本機伺服器，不會送到瀏覽器
- 摘要可用 Claude、OpenAI 或 Gemini；選 Gemini 時可以跟轉錄共用同一把 key

```
建會議 → 按開始錄音 → 講話（切段後出現逐字稿）→ 打字筆記 → 結束會議 → 產生會議紀錄
```

## 需要什麼

- **只想使用**：Windows 10／11，下載 `meeting-assistant.exe` 就好，**不用裝 Node**
- **要改程式**：Windows / macOS 都可，Node.js **22.18 以上**（會直接執行 `.ts`，開發時用 Node 26 測過）
- 瀏覽器：Chrome 或 Edge（錄線上會議的分頁音訊要用它們）
- 一組轉錄用的 key：
  - **Gemini**：到 [Google AI Studio](https://aistudio.google.com/apikey) 建立，有免費額度，不用先綁信用卡
  - **Typeless**：到 [Typeless Console](https://platform.typeless.com) 建立（`tls_sk_...`），預付制
- 一組摘要用的 LLM key：Claude、OpenAI 或 Gemini 任一（選 Gemini 可與轉錄共用）

## 安裝與啟動

### 方式一：執行檔（不用裝 Node）

1. 拿到 `meeting-assistant.exe`（約 100 MB，裡面已經包了 Node 與網頁），放在任何資料夾。
2. 點兩下。會開一個黑色視窗，瀏覽器自動打開 <http://127.0.0.1:8787>。
3. **黑色視窗要開著**，關掉就停止會議助手。重複點兩下只會再打開瀏覽器，不會開第二份。
   8787 被其他程式占用時會自動改用 8788、8789…，黑色視窗會顯示實際網址；這時深淺色偏好可能要重選一次。

第一次執行時，Windows 可能跳出「Windows 已保護您的電腦」：按「**其他資訊**」→「**仍要執行**」。
這是因為執行檔沒有付費的程式碼簽章，不是病毒警告。

### 方式二：從原始碼

```powershell
cd "路徑\meeting-assistant"
npm install
npm run build
npm start
```

打開 <http://127.0.0.1:8787>。

開發時用 `npm run dev`，前端會有熱更新（<http://localhost:5173>，API 仍在 8787）。

兩種方式的資料放在同一個地方（見下一節），換著用看到的是同一份會議與設定。

## 第一次啟動：選資料存放位置

第一次打開會先出現「**選擇資料存放位置**」，分兩個資料夾：

| 資料夾 | 存什麼 | 預設 |
| --- | --- | --- |
| 會議資料 | 錄音、逐字稿、筆記、截圖、會議紀錄 | `文件\Meeting Assistant` |
| 設定（含完整 API key） | `settings.json`、`.env` | `%APPDATA%\meeting-assistant` |

- 按「**瀏覽…**」會開 Windows 的選資料夾視窗，可以在裡面新增資料夾。
- 設定資料夾選在「文件」、「桌面」或 OneDrive 底下時會出現**紅字**：公司電腦常把這些資料夾同步到
  OneDrive，API key 會跟著上傳到雲端。沒有特別理由就用預設的位置。
- 兩個位置記在 `%APPDATA%\meeting-assistant\location.json`（只有路徑，沒有 key）。
  想重新跳出引導頁，關掉會議助手後刪掉這個檔再開。
- 之後可以在「設定」頁的「資料」區更換：
  - **會議資料夾**：換了以後舊會議**不會搬**，首頁只列新資料夾裡的會議。要沿用舊會議，用檔案總管把
    每場會議的資料夾拖到新位置（每場會議是一個獨立的資料夾），重新整理就會出現。錄音中不能換。
  - **設定資料夾**：按「搬到這裡」會把 `settings.json` 與 `.env` 一起搬過去，不用重填 key。
    新位置已經有同名檔時不會覆蓋，會請你換一個資料夾。

> **從舊版升級（原本用 `npm run dev` 的人）**：以前資料放在專案資料夾裡，改版後**不會自動搬**。
> 啟動時終端機會列出還留在專案裡的舊檔，照著搬：
> `server\.data\settings.json` 與專案根目錄的 `.env` → 設定資料夾；`meetings\` 底下每場會議的資料夾 → 會議資料夾。
> 搬完重新整理頁面即可，不用重啟。

## 第一次設定

到右上「**設定**」頁：

1. **選轉錄引擎**
   - **Gemini（免費額度）** — 貼上 Gemini API key，模型先用預設的 `gemini-3-flash-preview`（速度與品質最平衡）。
     免費層的每日請求數與每分鐘次數以 Google 官方公告為準；免費層的內容可能被用於改善服務，
     敏感的會議請改用付費 key。
   - **Typeless（付費）** — 貼上 `tls_sk_...`，選模型：
     Lite `$0.25/小時`、Pro `$0.50/小時`、Max `$2.50/小時`。一般中文會議用 **Pro** 就夠。
2. **摘要用的 LLM** — 選供應商、模型、貼 key。
   - 建議 `claude-opus-5-5`（要省錢選 `claude-sonnet-5-5`）或 `gpt-5`
   - 選 Gemini 時可以留白，直接沿用上面轉錄的 Gemini key

填好後，側邊欄「設定」旁的「需要設定」就會消失。

> **key 存在哪**：設定頁貼上後，key 只會送到本機伺服器，存在設定資料夾的 `settings.json`
> （位置見上一節，設定頁也會顯示）；瀏覽器之後只拿得到 `••••1234` 這種遮罩提示，拿不到完整 key。
>
> **也可以放 `.env`**（放在設定資料夾；執行檔版也可以放在 exe 旁邊，兩份都有時設定資料夾那份優先）：`GEMINI_API_KEY`、`TYPELESS_API_KEY`、
> `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`。只想用 `.env` 的話再加 `TRANSCRIBER=gemini`
> 與 `GEMINI_TRANSCRIBE_MODEL=gemini-2.5-flash`，改完不用重啟，下一次呼叫就會吃到。
> 兩邊都填時**設定頁優先**；設定頁目前沒有「清除」按鈕，想改用 `.env` 請用文字編輯器
> 打開設定資料夾的 `settings.json`，刪掉 `geminiApiKey` 與 `llmKeys.gemini` 後存檔。
>
> 伺服器預設只綁 `127.0.0.1`，同一個 Wi-Fi 的其他裝置連不到；要開放再設 `HOST=0.0.0.0`
> （這個 app 沒有登入機制，開放等於同網段的人都能看你的會議、用你的額度）。

## 開會流程

畫面左邊是所有會議的清單（可以搜尋），左下角是設定與深淺色切換（淺色／深色／跟隨系統）。

1. 按左上「**新會議**」，填**會議主題**、開始時間、音訊來源；選填會議目的、**與會者**（例如
   「王小明（PM）、Amy（廠商 IT）」，括號寫身分）、參考資料（上次紀錄、規格書、提案，可直接拖進來）。
2. 按「**建立並開始錄音**」（瀏覽器問麥克風權限時選允許）；只想先建好就按「只建立」，開會時從左側點進去開始。
   實體會議用「麥克風」；線上會議用「麥克風＋會議音訊」（見下一節）。
3. 開會。筆記在畫面中央，輸入框固定在頁尾（見「打字筆記」）；逐字稿在右側。
   上方的「**並排｜筆記｜逐字稿**」切換版面；並排時兩欄中間的線可以**左右拖曳**調寬（雙擊還原）。
4. 會議結束按「**結束會議**」，等最後一段轉錄完，會自動跳到紀錄頁。
5. 按「**產生會議紀錄**」，LLM 會依逐字稿＋筆記＋與會者＋參考資料寫出會議紀錄；右側可以切換筆記／逐字稿／參考資料對照。

**會議名稱**隨時都能點標題直接改；**開始時間**只有還沒開始錄音前能改（開始後計時與筆記時間點都依它）；
**與會者**開會中、會後都能點「修改」更新。

### 逐字稿為什麼不是即時跳字

兩個引擎都是**一段音訊處理完才回傳文字**，沒有逐字字幕、也沒有逐句時間戳：

- **Typeless**：每段音訊用一條 WebSocket 串流送出，關閉串流後回傳一次整理好的文字。
- **Gemini**：每段音訊先暫存在記憶體，切段時包成 WAV 上傳，請 Gemini 逐字轉錄。

所以我們用「切段」當成語意單位：

- 每 **3 分鐘**自動切一段（可在設定頁調 60–280 秒）
- 想立刻看到文字：按右上「**切段**」
- 打 `# 環節名稱`：標記會議進入下一個環節，**同時切段**，逐字稿就會跟環節對齊

> 如果一段不到 20 秒，`# 環節` 只會把標籤併進當前段，不會硬切出零碎段落。
> 手動按「切段」則一定生效。

### 錄線上會議（分頁／系統音訊）

`麥克風` 只收得到你；線上會議裡**對方的聲音是從喇叭或耳機放出來的，麥克風收不到**。
錄音頁的來源選單有三種：

| 來源 | 收什麼 | 適用 |
| --- | --- | --- |
| 麥克風 | 只有你 | 實體會議（預設） |
| 麥克風＋會議音訊 | 你＋對方 | 線上會議建議 |
| 只有會議音訊 | 只有對方 | 不想錄到自己 |

選了含「會議音訊」的選項，按開始錄音時 Chrome／Edge 會跳出分享視窗：

- **網頁版** Meet／Teams／Zoom：選那個**分頁**，勾「**分享分頁音訊**」。
- **桌面版** Teams／Zoom：選**整個螢幕**，勾「**分享系統音訊**」。
- 分享時沒勾音訊或按取消 → 會提示並自動退回只收麥克風，不會整場空白。
- 選單下方會顯示實際收到的裝置名稱；講話時時鐘旁的音量條會動，沒動就是裝置沒收到。

> 藍牙耳機的麥克風收不到對方聲音，而且通話模式會讓 Windows 的系統音訊常常抓不到；
> 要錄系統音，用有線耳機或喇叭最穩。

## 把既有的錄音檔轉成逐字稿

已經有錄音（手機、錄音筆、Teams 匯出）就不用重錄，直接把音檔轉成某場會議的逐字稿：

```powershell
node scripts/transcribe-file.ts "C:\Users\me\Downloads\會議.m4a" --meeting 2026-11-18-1400-xxx
```

- 檔案超過 15 分鐘會**先用 ffmpeg 真的切成每段 15 分鐘**，再逐段上傳轉錄
  （用 `--chunk-min 10` 可以調更短）。整場一次丟給 Gemini 會撞到輸出上限。
- 100 MB 以上的檔案走 Gemini **Files API**（上傳免費，檔案在 Google 保留 48 小時）。
  同一個檔案重跑第二次會自動沿用已上傳的版本，不會再傳一次。
- 逐字稿寫回會議資料夾的 `<id>/transcript.md`，會議狀態設為「已結束」，逐字稿依時間段落分節。
- 會議已經有逐字稿時要加 `--replace` 才會覆蓋。
- 跑到一半失敗不會白費：已完成段落留在 `transcript.partial.md`。

需要 **ffmpeg**（只要切段才需要）。三種裝法任選一種：

```powershell
winget install Gyan.FFmpeg                     # 裝完重開終端機
# 或下載 portable 版解壓到 tools\ffmpeg\bin\ffmpeg.exe（執行檔版：exe 旁邊的 tools\ffmpeg\bin\）
# https://www.gyan.dev/ffmpeg/builds/ffmpeg-release-essentials.zip
# 或在 .env 指定 FFMPEG_PATH=C:\path\to\ffmpeg.exe
```

長會議的實際數字（2 小時 m4a，112 MB）：切成 8 段各 15 分鐘（`-c copy` 切完常常多一段幾十秒的尾巴），
input 每段約 2.9 萬 tokens、輸出 3,000–5,000 字，整場約 5 分鐘跑完。
**用 `gemini-3-flash-preview`**（預設）。實測其他模型的問題：`gemini-3.5-flash-lite` 對大請求常回 503；
`gemini-3.1-flash-lite` 會卡在「重複同一句」直到撞輸出上限；`gemini-flash-latest` 品質好但光是
五個字的回答就花 106 秒（預設思考太久，而且不吃 `thinkingLevel: minimal`）。
程式偵測到尾端鬼打牆時，會砍掉重複並把該段切成兩半重跑（最多三層），所以偶爾會多花幾次請求。

## 打字筆記

輸入框直接打字就是一般筆記；前面加符號可以分類（符號後面要空白，全形符號也可以）：

| 前綴 | 類別 | 用在哪 |
| --- | --- | --- |
| `#` | 環節 | 標記「接下來要談什麼」，會同時切段 |
| `>` | 決議 | 已拍板的結論 |
| `!` | 待辦 | 會後要有人做的事 |
| `?` | 待確認 | 還沒答案的問題 |
| `*` | 想法 | 臨時想到的點子 |
| `-` 或不加 | 筆記 | 一般紀錄 |

也可以寫字母別名：`s:` 環節、`d:` 決議、`t:` 待辦、`q:` 待確認、`i:` 想法、`n:` 筆記。

例：

```
# 需求確認
? 舊資料 600 筆要不要先備份
! 寄報價給 Amy，週五前
> 這一版先做 markdown 匯出
```

### 貼上截圖

會議中截了圖（簡報、表格、白板），直接在錄音頁按 **Ctrl+V** 就會附到筆記：

1. 貼上後輸入框旁出現縮圖預覽（瀏覽器會先縮到長邊 1568px，一張約 200–400 KB）。
2. 順手打一句說明（例如「> Q3 營收表」，前綴分類照常用），按 Enter 送出；不打字直接 Enter 也可以。
3. 筆記欄會出現縮圖，點開看大圖；貼錯就按「刪除截圖」，圖片檔會一起刪掉、不會送進紀錄。

產生會議紀錄時，截圖會依時間編號（截圖 1、2…）跟著逐字稿和筆記一起送給 LLM，
圖上的數字、表格、決議會被整合進紀錄，句尾標「（截圖 N）」。

- 一場會議最多 **30 張**。
- 截圖常會帶到不相干的東西（聊天視窗、其他客戶的資料），這些都會被送到 LLM；貼之前留意，或貼完刪掉。
- 圖片存在會議資料夾的 `images/`，`notes.md` 用 `![](images/…)` 嵌入，用 Obsidian／VS Code 打開就看得到。

### 指令

| 指令 | 作用 |
| --- | --- |
| `/pause` `/resume` | 暫停／繼續收音（休息時間不計費） |
| `/seg 名稱` | 切段並標記接下來的環節名稱 |
| `/end` | 結束會議 |

## 產出在哪裡

會議紀錄存在會議資料夾（預設 `文件\Meeting Assistant`）底下的 `日期-時間-主題/`：

```
meetings/2026-11-18-1000-產品週會/
├── meeting.json     結構化資料（逐字稿、筆記、時間軸、引擎與模型）
├── transcript.md    逐字稿（依環節分段）
├── notes.md         筆記（依類別分組）
├── minutes.md       會議紀錄（LLM 產出，含 YAML frontmatter）
├── reference/       你上傳的參考資料
├── images/          會議中貼上的截圖（notes.md 會嵌入）
└── audio/mic.wav    原始錄音（設定頁可開關，1 小時約 110 MB）
```

`minutes.md` 有 frontmatter，可以直接丟進 Obsidian 當筆記：

```markdown
---
title: 產品週會
date: 2026-11-18
start: 10:00
end: 10:45
source: gemini
model: claude-sonnet-4-5
tags:
  - meeting
---
```

`source` 會是這場會議用的轉錄引擎（`gemini` 或 `typeless`）。
紀錄頁右上「開啟資料夾」會直接打開那一天會議的資料夾，「複製 markdown」可以貼到任何地方。

## 費用估算

以一場 **45 分鐘**的會議為例：

| 項目 | 計算 | 大約 |
| --- | --- | --- |
| Gemini 轉錄（免費層） | 3 段音訊上傳 | **$0**（受每日額度限制） |
| Typeless Pro | 0.75 小時 × $0.50 | **$0.38** |
| Typeless Lite | 0.75 小時 × $0.25 | $0.19 |
| Typeless Max | 0.75 小時 × $2.50 | $1.88 |
| LLM 摘要（Claude Sonnet） | 約 15–25k token 輸入 + 3k 輸出 | **$0.05–0.10** |
| 截圖（每張，送摘要時） | Claude／GPT 約 1–1.6k token；Gemini 約 258 token | 20 張約多 $0.06–0.10（Claude） |

只走 Gemini 免費轉錄＋免費層摘要，一場會議可以 **$0**，代價是每日次數與速度限制。
免費層的每日上限是**每個模型分開算**（例如 `gemini-3-flash-preview` 一天 20 次），
所以 2 小時會議（9 段＋重試）有機會當天用完；換一顆模型或等太平洋時間午夜重置即可。
現場錄音遇到「今天的額度用完」時會**自動換另一顆模型重送同一段音訊**，之後固定用新的那顆，
不會讓那幾分鐘的音訊直接消失（目前備援是 `gemini-flash-lite-latest` 與 `gemini-3-flash-preview`）。
每天一場 45 分鐘會議、用 Typeless Pro＋Claude 摘要，一個月約 **$10–14**。

## 常見問題

**完全免費可以嗎？**
可以。轉錄選 Gemini、摘要也選 Gemini，兩邊共用一把免費 key。限制是每日請求數與每分鐘次數，
以及免費層的內容可能被 Google 用於改善服務。要更穩、更不在意資料政策，再換成付費 key 或 Typeless。

**Gemini 轉錄的品質如何？**
`gemini-2.5-flash` 對清楚的中文會議通常夠用，但斷句與專有名詞不一定比 Typeless 好。
如果逐字稿品質是重點，可以用同一場會議切到 Typeless 比較一次。

**為什麼 Gemini 的切段上限是 280 秒？**
Gemini 的 inline 音訊請求有大小限制（約 20 MB）。16 kHz / 16-bit 單聲道在 280 秒時約 9 MB，
包成 WAV 再 base64 後仍在限制內。設定頁最多就是 280 秒。

**設定頁「測試連線」說沒有 API key，但 `.env` 明明有？**
先確認畫面上的**供應商**是不是你放 key 的那一家。測試連線用的是畫面上目前的供應商與模型（不必先按儲存），
key 的來源會顯示在結果後面，例如「key 來源：`.env` 的 `GEMINI_API_KEY`」。
沒在設定頁存過供應商時，程式會自動選「有 key 的那一家」。改過 `.env` 也不用重啟，存檔後下一次呼叫就會吃到。

**可以錄 Google Meet / Zoom 的聲音嗎？**
可以。錄音頁把音訊來源選成「**麥克風＋會議音訊**」（或「只有會議音訊」），按開始錄音後
在分享視窗選會議的**分頁**並勾「分享分頁音訊」；桌面版程式就選**整個螢幕**並勾「分享系統音訊」。
麥克風和系統音會混成一路再送去轉錄，所以你說的、對方說的都會在同一份逐字稿裡。
瀏覽器不支援純音訊的分頁分享，所以一定要分享畫面（分頁或螢幕），音訊才會一起過來。

**錄到一半關掉瀏覽器會怎樣？**
伺服器會把當前那段收尾、存檔，會議停在「暫停」。重新打開那個會議按「繼續收音」就能接著錄。

**可以換成別的轉錄服務嗎？**
可以。`server/relay.ts` 依 `meeting.engine` 分支，`server/gemini.ts` 是 Gemini 的實作，
換服務大約是新增一個同介面的 `transcribePcm()`。

**可以不要保留錄音嗎？**
設定頁的「保留原始錄音」預設關閉，開啟才會寫 `audio/mic.wav`（選了會議音訊時，檔案裡是
麥克風＋系統音訊混好的版本）。

**逐字稿或筆記有錯、會後想補充怎麼辦？**
逐字稿在錄音頁、紀錄頁都可以**直接點進去改**（錯字、專有名詞、聽漏的補充），停手 0.8 秒或離開就自動存，
段落標題旁會出現「已校正」；轉錄失敗的段落也能打字補上。紀錄頁的筆記一樣能直接改內容、點標籤換類型、刪除，
最下面還能補「會後補充」的想法。紀錄產生後才改的話，標題下會提醒「按重新產生讓紀錄跟上」。

## 開發

```powershell
npm test              # 單元測試（prefix 解析、markdown、格式化、WAV 檔頭）
npm run typecheck     # tsc --noEmit
npm run smoke         # 假 Typeless + 假 Gemini + 假 LLM，兩條轉錄路徑都跑，再走一次第一次啟動流程；不需要任何 key
npm run build         # 型別檢查 + vite build
npm run e2e           # headless Edge + 假麥克風，真的走一次瀏覽器流程（需先 build）
npm run typography    # 中文孤行檢測，桌機 1440px 與手機 390px
npm run preview       # 拍首頁／紀錄頁／設定頁截圖到 preview/（需先 build + npm start）
npm run package       # 打包成 release/meeting-assistant.exe（需要 Node 25.5 以上）
npm run smoke:exe     # 對打包好的 exe 跑一次 smoke
```

### 打包執行檔

`npm run package` 用 Node 內建的 SEA（single executable application）：

1. `npm run build` 建置前端到 `dist/`
2. 用 rolldown 把 `server/` 打成一個 CommonJS 檔
3. 把 `dist/` 的檔案當成 SEA asset 塞進 exe（伺服器用 `node:sea` 的 `getAsset` 讀）
4. `node --build-sea` 產生 `release/meeting-assistant.exe`

**用哪個 Node 打包，exe 裡就是哪個 Node**，所以要在 Node 25.5 以上執行。目前只出 Windows 版；
程式碼本身跨平台，要出 Mac 版得在 Mac 上打包。交出去之前跑一次 `npm run smoke:exe`。

專案結構：

```
server/     API、Typeless 串流 relay、Gemini 轉錄、檔案存取、摘要 prompt、LLM 呼叫
src/core/   前後端共用：型別、筆記解析、markdown 渲染、格式化
src/ui/     極簡前端：首頁、錄音頁、紀錄頁、設定頁
public/     pcm-worklet.js（音訊 → 16k PCM16）
scripts/    dev / smoke / e2e / typography / preview / package（打包 exe）
```

## 已知限制

- 沒有即時字幕，逐字稿要切段後才出現
- Gemini 免費層有每日與每分鐘請求上限；超過時要等額度重置或換付費 key
- 沒有講者分離（講者 A／B 不會自動標）；與會者名單只用來把人名寫對、讓摘要分清角色
- 沒有 Obsidian / Notion 同步，也沒有待辦自動推送
- 一次只能錄一場會議
